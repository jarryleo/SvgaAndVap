# 将 svga/vap 的 bitmap 解码与下载逻辑合并提升到 lib_base（以 VAP 代码为准）

## Context

`lib_svga` 与 `lib_vap` 各自维护了一套几乎相同的 bitmap 解码器（7 个文件的 Decoder 家族）、bitmap 下载器（内存缓存→磁盘缓存→网络下载）和文件下载器，长期双份维护。`lib_base`（namespace `cn.leo.base`）已存在并已以 `api` 透出 okhttp + coroutines，两个库都已依赖它。目标：把这套逻辑以 VAP 实现为准合并进 `lib_base`，两边共用。

已确认的决策：**① bitmap 缓存统一共享**（内存 LRU + `cacheDir/bitmap/`，两库同 URL 只存一份，旧缓存作废）；**② 干净替换**（删除两库中被提升的类，不留 typealias）；**③ HTTPS 两个库统一采用忽略证书校验（trust-all）**，即把 SVGA 的 trust-all 配置应用到 base 共享的 OkHttpClient 上。

注意：`lib_vap/.../BitmapSampleSizeCalculator.kt` 工作区有一处未提交的采样修复（halfHeight→height），提升时以工作区版本为准。git 状态里 svga 资源的 AD 变更与本任务无关，不处理。

## 一、lib_base 新增（包 `cn.leo.base`，全部取自 VAP 代码，去掉 `internal`）

**bitmap（`lib_base/src/main/java/cn/leo/base/bitmap/`）**
- `BitmapDecoder.kt` — 抽象基类（两遍解码 + RGB_565），逐字取 VAP 版
- `BitmapSampleSizeCalculator.kt` — 取 VAP 工作区已修复版本
- `BitmapByteArrayDecoder.kt` / `BitmapFileDecoder.kt` / `BitmapInputStreamDecoder.kt` / `BitmapResDecoder.kt` / `BitmapUrlDecoder.kt` — 逐字迁移（UrlDecoder 走 OkHttp）

**download（`cn/leo/base/download/`）**
- `FileDownloadManager.kt` — VAP 版逐字迁移（含 DownloadStatus/DownloadState/DownloadException）；companion 的 `okHttpClient` 构建时套用从 SVGA `SVGABitmapUrlDecoder` 提取的 trust-all 配置（sslSocketFactory + hostnameVerifier）
- `BitmapDownloadInterface.kt` — 逐字迁移
- `BitmapDownloader.kt` — VAP 版；磁盘缓存路径改用 base 的 `BitmapDiskCache`（替代 `VapFileCache.buildCacheBitmapFile(context).first()`），日志改用 `BaseLog`，其余流程（30s 超时、内存→磁盘→下载、下载去重队列）不变

**cache（`cn/leo/base/cache/`）**
- `BitmapCache.kt` — 内存 LRU（VAP 版），`createKey` 内联 MD5（输出格式与两库现状完全一致）
- `BitmapDiskCache.kt` — 新增小工具：`buildKey(str)`（MD5 hex）、`cacheFile(context, key)` → `cacheDir/bitmap/<key>.png`（自动建目录）、`clear(context)`（沿用两库相同的递归删除逻辑）

**log（`cn/leo/base/log/`）**
- `BaseLog.kt` — 仿 VAP `ALog` 的可插拔日志（isDebug + 接口），供 base 内部使用

lib_base 无需改 build.gradle.kts（AGP9 内建 Kotlin；okhttp/coroutines 已是 api 依赖，与 lib_vap 现状同构）。

## 二、lib_vap 改动

- **删除**：`bitmap/` 整包（7 文件）、`download/` 整包（3 文件）、`cache/BitmapCache.kt`
- `AnimViewExt.kt`：解码器 import 换成 `cn.leo.base.bitmap.*`；`downloadImageFile` 里 `VapFileCache.buildCacheBitmapFile(buildCacheKey(url), context).first()` 改为 `BitmapDiskCache.cacheFile(context, BitmapDiskCache.buildKey(url))`（原始图片文件缓存也归入 `cacheDir/bitmap/`）
- `VapManager.kt`：download/cache 相关 import 换成 base 包；init 时记录 applicationContext；`clearCache()` = `VapFileCache.clearCache()` + base `BitmapCache.INSTANCE.clear()` + `BitmapDiskCache.clear(appContext)`
- `VapFileCache.kt`：删除只被迁移代码使用的 `buildCacheBitmapFile`；`buildCacheKey`/`buildCacheFile`（mp4 缓存）保留，AnimViewExt 仍在用

## 三、lib_svga 改动

- **删除**：`bitmap/` 整包（7 文件）、`download/BitmapDownloader.kt`、`cache/SVGABitmapCache.kt`
- `SVGADynamicEntity.kt` / `SVGAVideoEntity.kt`：解码器 import 换成 base 包；`BitmapDownloader.downloadBitmap(url, w, h)` 改为 base 版 `downloadBitmap(context, url, w, h)`（调用处 context 可用，同方法内已在用 `context.assets`）
- `SVGAManager.kt`：`SVGABitmapCache.INSTANCE.clear()` 两处改为 base `BitmapCache.INSTANCE.clear()`；`clearCache()` 增加 `BitmapDiskCache.clear(appContext)`；`SVGAMemoryCache`（视频实体缓存）与 HttpResponseCache 机制不在本任务范围、不动（FileDownloader 改走 OkHttp 后 HttpResponseCache 对 svga 下载失效，属预期行为变化）
- `download/FileDownloader.kt`：**保留类与 `resume(url, complete, failure): Job` 签名**（公开可覆写的 API），保留 SVGAFileCache 缓存路径、tmp 文件发布、rename 失败回退拷贝、`isActive` 取消语义与注释；仅把 HttpURLConnection 段替换为 base `FileDownloadManager.okHttpClient`（已带 trust-all）流式下载，删除 SSL trust-all 代码（已上移 base）和 HttpResponseCache 告警日志

## 四、app 模块

无需改动（仅使用 VapManager/SVGAManager/SVGAImageView 等门面）。
